# Syllogimous v5 — техническое задание для Claude Code

Переработка `syllogimous-v4.1` в тренажёр реляционной интеграции (RI), в котором ответ нельзя получить шаблоном, нагрузка на связывание отношений задаётся явно и измеряется, а форматы и структуры меняются достаточно, чтобы навык не «запирался» в одном типе задач.

Научное обоснование каждого решения — в документе «Научная база: Gf, реляционная интеграция и перенос» (выдан пользователю отдельно). Здесь — только то, что нужно для реализации, с короткой ссылкой на причину.

## 0. Как работать с этим документом

1. **Выполняй фазы строго по порядку.** Пользователь будет давать команды вида «Выполни фазу 1A». Не начинай следующую фазу без команды.
2. **Каждая фаза заканчивается так:** все тесты зелёные (`npm run test:engine`, затем `npm run build:verify`), для фаз 1+ — `npm run audit` с отчётом, затем короткий отчёт пользователю: что сделано, какие числа дал аудит, какие отступления от ТЗ и почему. Если репозиторий под git — один коммит на фазу (или подфазу).
3. **Не переусложняй.** Запрещено возвращать машинерию удалённого экспериментального модуля: «сертификаты», версионированные семантические грамматики, IndexedDB-репозитории, «защищённые оценочные манифесты», Web Worker для обычной генерации. Движок — набор чистых функций на TypeScript + тесты. Хранилище — `localStorage`, как сейчас.
4. **Чистый движок.** Всё в `src/app/syllogimous/engine/` — без импортов Angular, DOM и `localStorage`. Angular-слой только вызывает движок и хранит состояние.
5. **Детерминизм.** Любое задание полностью определяется `(engineVersion, family, level, params, seed)`. Никаких `Math.random()` в движке и никаких бюджетов по реальному времени, меняющих результат: только счётчики попыток.
6. **Язык.** Интерфейс и тексты заданий — на русском. Код, идентификаторы, комментарии — на английском.
7. **Если ТЗ расходится с реальностью кода** — действуй в духе ТЗ, а отступление запиши в `docs/V5_NOTES.md` (раздел «Отступления»), одной-двумя строками.
8. **Данные пользователя не теряем.** Старые записи истории, счёт, настройки должны продолжать загружаться (см. фазу 2, миграции).
9. **Karma** (`npm test`) требует Chrome. Если его нет — `ng test --watch=false --browsers=ChromeHeadless`; если нет и его — отметь в отчёте, что Karma не запускался. Движок проверяется Vitest и от браузера не зависит.

## 1. Цель и инварианты, которые нельзя нарушать

**Цель.** Каждое задание должно требовать совместного удержания и интеграции нескольких отношений; любой путь к ответу без такой интеграции (подсчёт слов, приор по формулировке, чтение порядка из инструкции, локальная эвристика) должен давать точность на уровне случайности. Дополнительно — тренировать то, что исследования связывают с Gf: гибкое связывание при случайном порядке доступа, многомодельное рассуждение, подавление интерференции, отображение структур, сегментацию (выбор нужных посылок).

| # | Инвариант | Почему (кратко) |
| --- | --- | --- |
| I1 | Точность каждого бота-эвристики на сгенерированном потоке ≤ шанс + 5 п.п.; «обученного» бота на поверхностных признаках ≤ шанс + 7 п.п. Проверяется автоматически (`npm run audit`). | Лазейка поглощает нагрузку и формирует узкую рутину, не переносящуюся на другие задачи. |
| I2 | С уровня 4: ответ **не выводится** из посылок, упоминающих хотя бы одну сущность вывода («нелокальность»), и минимальная опора σ ≥ 3. | Связь WM–Gf держится на гибком связывании, которое нельзя заменить локальным чанкингом. |
| I3 | По умолчанию ответ трёхзначный: «Следует / Противоречит / Неизвестно». Классы сбалансированы ≈ 1/3. | «Неизвестно» требует проверить все модели, а не одну предпочтительную; шанс угадать падает с 50% до 33%. |
| I4 | Сложность многомерная (σ, ширина, арность, сходимость, неопределённость, дистракторы, приманки), а не «число посылок». | Длинная цепочка решается последовательными тернарными шагами и грузит память, а не интеграцию. |
| I5 | Вариативность: топологии (цепь/дерево/DAG/цикл), формулировки, имена, фреймы, форматы ответа; запрет повтора структурного «отпечатка» в окне из 50 заданий. | Навык, натренированный на одном материале, не переносится даже на ту же операцию с другим материалом. |
| I6 | Чередование фреймов: в обычной игре два задания одного семейства подряд запрещены (если включено ≥ 2 семейств). | Чередование заставляет распознавать структуру, а не повторять последнюю процедуру. |
| I7 | Адаптивность: взвешенная лестница на ≈ 75% верных (3 варианта) / 80% (2 варианта). | Длительное рассогласование требований и ресурсов без провала. |
| I8 | После ответа — разбор: решающие посылки, контрмодель, тип ловушки, подсказка-стратегия. | Сравнение и принцип после попытки дают абстракцию схемы. |
| I9 | Детерминизм по seed; движок без Angular. | Воспроизводимость, тестируемость, аудит. |
| I10 | Корректность: каждый ответ вычислен точным решателем; для малых размеров — перекрёстная проверка независимым перебором в тестах. | Ошибка в задании учит неверному. |
| I11 | Инверсии (красные слова) — отдельный параметр «декодирования», не считаются ростом сложности RI. | Они грузят чтение, а не связывание. |
| I12 | Честный интерфейс: никаких «IQ», «процентилей», обещаний роста интеллекта. Уровень в тренажёре ≠ Gf. | Самообман мешает корректировать тренировку. |

### 2.2 Почему нельзя «подкрутить» старые генераторы

Структурно все цепочечные типы порождают **простую цепь** посылок, а вывод для «Равенства» всегда о концах этой цепи. Ложные выводы строятся другим процессом, чем истинные, поэтому у них другая поверхностная статистика. Это не лечится заплатками — нужен единый конвейер «сначала целевой ответ и профиль подсказок, потом конструкция, потом проверка решателем».

### 2.3 Аудит v4.1 (воспроизводится скриптами из `audit-baseline/`)

Боты видят только отрисованный текст. Шанс при двух вариантах — 50%.

| Тип | Лазейка | Точность без интеграции | Причина |
| --- | --- | --- | --- |
| Равенство/противоположность | Чётность числа «противоположен» во всех посылках | 100% (66–74% с метаотношениями) | Посылки — всегда простая цепь, вывод — о её концах |
| Сравнение чисел/времени | «Счёт побед» каждого слова | 100% (2–3 посылки), 85% (5), 66% (12) | Всегда цепь; концы видны локально |
| Силлогизмы «Каньон» | Квантор вывода: «Все…» верно в 1–8%, «Некоторые… не» — в 72–76% | 74–80% по одному квантору; эффект атмосферы 70–78% | Ложный вывод строится иначе, чем истинный |
| Силлогизмы «Фредо» | То же | 62–70% | 2 посылки + шум |
| Линейный и круговой порядок | Строка инструкции перечисляет предметы **в истинном порядке** | 100% без чтения посылок | `formatArrangementInstruction(words, …)` получает массив в порядке позиций |
| Направления 2D | «в соседней клетке» в выводе всегда верно | 100% на 19–31% заданий; бот 59–70% | При порче вывода `adjacent = false` |
| Направления 2D + инверсии | Красная диагональ при инверсии одной оси — **текст неоднозначен** (баг) | 58% заданий; точный решатель по тексту — 82–87% | `formatDirectionRelationship` красит всю диагональ |
| Направления 3D | Шаг больше размера сетки → всегда «неверно»; «та же точка» → всегда «верно» | 0% / 100% верных в подгруппах | Искажение «+1 шаг» выходит за границу |
| Сравнение графов | Сравнить степени вершин | 97–100% (без метаотношений) | Искажение почти всегда меняет степени |
| Аналогии на порядке | «Такое же» при 5+ посылках почти всегда неверно | 11–31% верных против 70–88% | Нет балансировки |
| Логические связки | XOR/XNOR чаще верны | 59–60% | Слабая балансировка |

### 2.4 Почему одной балансировки ответов мало (проверено прототипом)

Прототип для порядка с посылками «больше» и «между»: только балансировка классов ответа оставила бота «счёт побед» на 66–79% при шансе 33%. Отбор из пула кандидатов с «дефицитной» стоимостью перегнул в обратную сторону (21–28% — это тоже подсказка, «делай наоборот»). Сработало только так: **заранее выбрать пару (целевой ответ, желаемое мнение бота) независимо друг от друга, затем построить посылки с конструктивными приманками, которые реализуют оба, и проверить решателем**. Результат: боты 28–38% при шансе 33%, генерация p50 0.2–3 мс, p95 7–32 мс (Node, без оптимизаций). См. `audit-baseline/proto-constructive-order.ts`.

RNG — порт проверенной пары xmur3 + sfc32 с тремя независимыми потоками (`semantic`, `presentation`, `scheduler`), чтобы изменение оформления не меняло логическое задание:

```ts
export class Rng {
  private next: () => number;
  constructor(private readonly seedLabel: string) { const h = xmur3(seedLabel); this.next = sfc32(h(), h(), h(), h()); }
  float(): number { return this.next(); }
  int(n: number): number { return Math.floor(this.next() * n); }
  chance(p: number): boolean { return this.next() < p; }
  pick<T>(a: readonly T[]): T { return a[this.int(a.length)]; }
  shuffle<T>(a: T[]): T[] { for (let i = a.length - 1; i > 0; i--) { const j = this.int(i + 1); [a[i], a[j]] = [a[j], a[i]]; } return a; }
  fork(label: string): Rng { return new Rng(`${this.seedLabel}:${label}`); }
}
export const streams = (seed: string) => ({ semantic: new Rng(seed + ':sem'), presentation: new Rng(seed + ':pres'), scheduler: new Rng(seed + ':sch') });
```

### 4.3 Конвейер генерации (`engine/generate.ts`)

```text
generate(spec: { family, level, seed, format, plan, prevNames? }):
  p     = ladder(family, level ± jitter)                 // 4.6
  rngs  = streams(seed)
  for attempt in 1..MAX_ATTEMPTS (60):
    w        = plugin.sampleWorld(rngs.semantic, p)
    premises = plugin.buildPremises(rngs.semantic, w, p, plan)      // строит приманки под plan.cue
    for q in shuffle(plugin.candidateQueries(premises, ids, p)):
      if statedDirectly(q, premises): continue                       // та же пара/тройка и тот же тип отношения
      a = plugin.classify(premises, q, ids);       if a ≠ plan.target: continue
      if a ≠ 'undetermined':
        S = minimalSupport(plugin, premises, q, a, p.sigmaMax)       // 4.4
        if !S or |S| < p.sigmaMin: continue
        if p.requireNonLocal and myopic(premises, q) ≠ 'undetermined': continue
        if p.requireConvergent and not convergent(S, q): continue
      if lureOf(q, premises, a) ≠ plan.lure and attempt < MAX/2: continue
      if not botsMatch(plan.cue, premises, q) and attempt < MAX*0.75: continue
      return finalize(...)          // метрики, отображение, рендер, разбор, отпечаток
  fallback: ослаблять по порядку [cue → lure → requireConvergent → sigma ±1]; записать в metrics.relaxations
  если и так не найдено: повтор с seed + ':r1' … ':r5'; дальше — исключение (это баг генератора, его должны ловить тесты)
```

- **Целевой ответ никогда не ослабляется** — иначе нарушится баланс классов.
- **Формат `choice`** («Кто третий по величине?», «Кто стоит k-м слева?»): варианты — все имена + «Нельзя определить»; целевой ответ — `entailed` (верна ровно одна сущность во всех моделях) или `undetermined` (верный вариант — «Нельзя определить») в пропорции 3:1.

- **`plan` задаёт планировщик** (4.8), а не генератор: целевой ответ берётся из перемешанного «мешка» {E, C, U}×4 на семейство, профиль подсказок — из **независимого** мешка желаемых мнений ботов семейства. Именно независимость делает мнение бота неинформативным (см. 2.4).
- **`buildPremises` строит приманки конструктивно**, а не надеется на отбор. Пример для порядка (проверен): выбрать пару вывода, затем добавлять истинные в мире сравнения, задевающие сущности вывода так, чтобы «счёт побед» указывал на желаемое мнение бота; проверить решателем, что ответ, σ и нелокальность сохранились. Для каждого семейства приманки описаны в разделе 5.
- **`statedDirectly`** — вывод не может совпадать по набору сущностей и типу отношения ни с одной посылкой (включая обратную формулировку).
- **`finalize`**: порядок показа (4.7), инверсии, имена, рендер, разбор (4.9), `fingerprint`.

### 4.4 Минимальная опора, нелокальность, сходимость (`engine/core/support.ts`)

- **σ** — минимальное по размеру подмножество посылок S, из которого следует ответ (`entailed`: S ⊨ q; `contradicted`: S ⊨ ¬q). Поиск по размерам 1…σmax с ранним выходом; сохраняй найденное S для разбора.
- Ускорение: рассматривать только посылки из компоненты связности сущностей вывода в гиперграфе посылок.
- `supportDomain: 'restricted'` — подмножество решается только на своих сущностях. Корректно для относительных отношений (больше/меньше/между, равен/противоположен, кванторы, разности координат, булевы правила). Для позиционных миров (ряд, круг) «ограниченный» означает инъекцию сущностей подмножества в **полный** набор позиций 1…n (остальные сущности всегда можно рассадить на свободные места) — это тоже точно. Для иерархии (прямое вхождение глобально) — `'full'`.
- **Нелокальность**: `myopic(P, q)` = `classify` на посылках, упоминающих хотя бы одну сущность вывода. Задание нелокально, если `myopic` = `undetermined`, а полный ответ — нет.
- **Сходимость**: S — НЕ простая цепь q₀–x₁–…–q₁ из бинарных посылок. Иначе говоря, сходимость есть, если в S есть посылка арности ≥ 3, или сущность степени ≥ 3, или |S| больше длины кратчайшего пути между сущностями вывода.

### 4.5 Метрики (`engine/core/metrics.ts`)

Заполни `ItemMetrics`. `modelsLog2` — по перечислению (обрезка на 2¹⁶). `distractors` — посылки вне S; `attachedDistractors` — из них имеющие общую сущность с S. `discontinuity` — доля соседних по показу пар посылок без общей сущности.

### 4.6 Лестница сложности по умолчанию (`engine/difficulty/ladder.ts`)

Уровень L — вещественное 1…20. Перед каждым заданием `L' = L + U(−1, +0.5)` (вариативность). Параметры — функции от L' (семейство ограничивает своими `limits` и допустимыми значениями):

| Параметр | Формула / значения |
| --- | --- |
| `n` (сущности) | `clamp(3 + floor((L+1)/3), min, max)` → L1: 3, L2: 4, L5: 5, L8: 6, L11: 7, L14: 8 |
| `sigmaMin` | L<3 → 2; L<10 → 3; L<15 → 4; иначе 5 |
| `sigmaMax` | `sigmaMin + (L<3 ? 0 : 1)`, не больше возможностей семейства |
| `requireNonLocal` | L ≥ 4 |
| `pTernary` (доля посылок арности 3) | `clamp(0.05·(L−2), 0, 0.5)` |
| `pConvergent` (доля заданий, где сходимость обязательна) | `clamp(0.1·(L−1), 0, 0.8)` |
| `distractors` | L<3 → 0; L<6 → 1; L<10 → 2; иначе 3 |
| `lureMix` | L<2: только `none`; L<3: +`reversal`; L<5: +`possible`; L<8: +`nearMiss`; иначе +`surface` |
| `order` | L<6: random; L<10: discontinuous с p = 0.5; иначе discontinuous 0.7 + adversarial 0.3 |
| `negationRate` | если включены инверсии: L<7 → 0, иначе `min(0.3, 0.05·(L−6))` |
| `metaRate` | если включены метаотношения: L<10 → 0, иначе `min(0.3, 0.05·(L−9))` |
| `confusableNames` | L<8 → 0, иначе `min(0.5, 0.1·(L−7))` |
| `carryOverNames` | L<10 → 0, иначе `min(0.3, 0.1·(L−9))` |

Ключ: **ни один параметр не растёт один** — лестница по очереди поднимает разные измерения. Числа — стартовые; держи их в одном конфиге, чтобы пользователь мог править.

### 4.7 Предъявление (`engine/core/presentation.ts`, `engine/core/names.ts`)

**Порядок посылок:**
- `random` — случайная перестановка;
- `discontinuous` — жадно: следующая посылка без общих сущностей с предыдущей, пока возможно;
- `adversarial` — посылки опоры разнесены (первая/середина/последняя), между ними дистракторы.

**Имена.** Новый пул по умолчанию — **кириллические псевдослова CVC** (как бессмысленные слоги в SMART: правило, а не знакомое слово). Согласные `БВГДЖЗКЛМНПРСТФХЦЧШ`, гласные `АЕИОУЫЭЮЯ`. Исключить: (а) нарушения орфографии (ЖЫ, ШЫ, ЧЯ, ЩЯ, ЧЮ, ЖЯ, ШЯ, ЖЮ, ШЮ, ГЫ, КЫ, ХЫ, ЦЮ, ЦЯ); (б) реальные слова и аббревиатуры — файл `names.blocklist.ts` (собери список трёхбуквенных русских слов максимально полно, включая грубые и обсценные корни); (в) пары, отличающиеся только Е/Э или И/Ы, в режиме `distinct`. Старые пулы (`NOUNS`, латинские CVC, эмодзи) остаются как опции.

Режимы имён:
- `distinct` — разные первые буквы в пределах задания;
- `confusable` — пары с общей первой буквой или различием в одну букву (ВОЛ/ВАЛ, ДЕК/ДЕМ);
- `carryOver` — 1–2 имени из предыдущего задания в **новых ролях** (тренирует отцепление от старых связей); Angular-слой передаёт `prevNames`.

**Инверсии** (красное слово = противоположное значение, как сейчас, класс `is-negated`). Только для отношений с явной парой-антонимом (больше↔меньше, раньше↔позже, левее↔правее, севернее↔южнее, восточнее↔западнее, выше↔ниже, равен↔противоположен, «в одной группе»↔«в разных группах», «Все»↔«Ни один» и т. п.). Никогда для «рядом», «напротив», «между». **Исправить баг 2D:** если инвертирована одна ось диагонали, выводи двумя компонентами («на 1 шаг <красн>южнее</красн>, на 1 шаг восточнее»), красным — только инвертированная.

### 4.8 Планировщик в движке (`engine/difficulty/scheduler.ts`)

Чистые функции над сериализуемым состоянием (хранит Angular-слой):
- мешки целевых ответов на семейство: перемешанные {E, C, U}×4 (для бинарного формата {E, C}×6);
- мешки желаемых мнений ботов на семейство — **независимо** от мешка ответов;
- мешки типов приманок по `lureMix`, **совместимых с целевым ответом**: «Следует» — {none, surface}; «Противоречит» — {none, reversal, nearMiss, surface}; «Неизвестно» — {none, possible, surface}. Доля `surface` одинакова во всех трёх классах, иначе сама совместная встречаемость слов вывода в одной посылке станет подсказкой;
- формат: из настроек (тернарный или бинарный); семейства, поддерживающие `choice`, получают до 20% заданий-выборов; семейство `binary` всегда в бинарном формате;
- выбор семейства: веса `w_f = 1 + 0.5·(L_max − L_f)/max(1, L_max − L_min)`; 0 для семейства предыдущего задания (если включено ≥ 2), ×0.5 — если оно было два задания назад;
- окно отпечатков на 50 заданий: при совпадении — до 3 перегенераций с новым seed. Отпечаток = семейство + мультимножество видов посылок + канонизированная последовательность степеней графа посылок + вид вывода + ответ.

### 4.9 Разбор (`engine/explain/*`)

- `supportDisplayIdx` — S, переведённое в порядок показа.
- `entailed`/`contradicted`: одна модель (если ответ определён однозначно — единственная) + подсветка S.
- `undetermined`: **две** модели — где вывод выполняется и где нет.
- Тип ловушки → `lureNote`: `possible` — «Это верно в одном из возможных миров, но не во всех»; `reversal` — «Направление отношения перепутано»; `nearMiss` — «Отношение то, но величина (шаг, расстояние) другая»; `surface` — «Эти слова стояли рядом в посылке, но связь между ними другая».
- Модели — по-русски, компактно, формат на семейство (раздел 5).

### 4.10 Боты и аудит (`engine/audit/*`)

**Общие боты** (видят только `Item` без поля `answer`):
- `prior` — мажоритарный класс по (тип вывода, полярность, инверсия), обучается на обучающей части выборки;
- `myopic` — точный решатель только на посылках, касающихся сущностей вывода;
- `oneModel` — строит `preferredModel` и отвечает `entailed`, если вывод в ней верен, иначе `contradicted`; «Неизвестно» не говорит никогда. **Это не лазейка** (он интегрирует все посылки), поэтому из гейтов исключён, но в отчёте: среди `undetermined` доля, где он говорит `entailed`, должна быть 40–60% (половина «неизвестных» — ловушки «возможно, но не обязательно»);
- `degree` — у какой сущности вывода больше упоминаний, та «больше/левее/…»;
- `learned` — мультиномиальная логистическая регрессия (softmax, L2) на `features()` + общих признаках: число посылок каждого вида, число инверсий и метаотношений, вид и полярность вывода, степени сущностей вывода, встречались ли они в одной посылке, позиции их первого упоминания, листья ли они. Обучение на 2·`AUDIT_N` заданий, проверка на `AUDIT_N` других заданий, на уровнях 6 и 14.

Размер выборок задаёт переменная окружения `AUDIT_N` (по умолчанию 1 500; для быстрой проверки во время разработки — 300). Ориентир для полного прогона — 10–15 минут; если дольше 20 минут, профилируй генератор, а не уменьшай `AUDIT_N`.

**Семейные боты** — в разделе 5.

**Гейты** (`families.audit.ts`, для каждого семейства на уровнях 2, 6, 10, 14 и 18, где семейство их поддерживает, N = `AUDIT_N`; считаются на тернарном формате, бинарный формат — отдельный прогон только для баланса):

| Проверка | Порог |
| --- | --- |
| Баланс классов | тернарный: каждый класс 30–36.7%; бинарный: 47–53% |
| Каждый эвристический бот (кроме `oneModel`) | ≤ доля мажоритарного класса + 5 п.п. |
| `myopic` на уровнях ≥ 4 | ≤ шанс + 5 п.п. |
| `learned` | ≤ шанс + 7 п.п. |
| Ослабления | ≤ 10% заданий |
| Время генерации (Node) | p95 ≤ 40 мс для семейств обычной игры |
| Формат `choice` | боты `degree` и «первое упомянутое» ≤ шанс + 7 п.п.; доля «Нельзя определить» 25% ± 3 п.п. |

Отчёт — `reports/cue-audit-v5.md` (таблица как в 2.3, но «до/после») и `reports/cue-audit-v5.json`. Провал гейта = провал фазы; чинить генератор (приманки, стратификацию), а не порог.

### 4.11 Тесты корректности (`*.test.ts`)

Для каждого семейства и уровней {1, 4, 8, 12, 16}, по 300 заданий с фиксированными seed:
1. Повторная классификация решателем совпадает с `answer`; посылки совместны.
2. σ в целевом диапазоне (или зафиксировано ослабление).
3. Ни одна посылка не формулирует вывод напрямую.
4. Рендер: нет `undefined`, теги `<span>` сбалансированы, в видимом тексте нет латиницы, кроме имён из латинского пула.
5. Детерминизм: одинаковый seed → идентичный JSON задания.
6. **Независимый оракул** на малых размерах (отдельная, предельно простая реализация полным перебором): `groups` (2ⁿ), `syllogism` (перебор занятости областей диаграммы Венна для ≤ 4 терминов), `dir2d/3d` (перебор координат в коробке 0…4 при n ≤ 4), `graph` (перестановки), ручные фикстуры для семантики круга и «между».

## 5. Семейства фазы 1

Для каждого: мир → посылки → вопросы → решатель → приманки и контроль подсказок → семейные боты → формат модели в разборе. Тексты — в `render/ru/<семейство>.ts`; шаблоны держат имена в именительном падеже, где это возможно («A больше, чем B»; «A и B стоят рядом»; «Из A, B и C посередине стоит B»). С псевдословами падежи не видны, со словами из `NOUNS` это заметно снижает неграмотность.

### 5.1 `groups` — «Равенство и противоположность» (EnumQuestionType.Distinction)

- **Мир:** `color[e] ∈ {0,1}`, `color[e0] = 0` (симметрия).
- **Посылки:** `same(a,b)` «A равен B»; `opp(a,b)` «A противоположен B»; `meta(a,b,c,d, same|opp)` «Отношение A к B такое же, как отношение C к D» / «…противоположно отношению C к D» — ограничение `(x_a⊕x_b) = (x_c⊕x_d)` или `≠`; арность 4, появляется по `metaRate`.
- **Вопросы:** `same(a,b)` / `opp(a,b)`; показанное слово вывода выбирается **независимо** от ответа.
- **Топология:** случайный остов + 0–2 согласованных лишних ребра (циклы) + метаограничения. Вывод — никогда не «концы единственной цепи». На уровнях ≥ 4 граф посылок для определённых ответов связен; дистракторная компонента есть и у определённых, и у неопределённых заданий, чтобы «есть ли вторая компонента» не было подсказкой.
- **Решатель:** перебор 2ⁿ⁻¹ (n ≤ 10).
- **Контроль подсказок (конструктивно):** бот `parity` (чётность всех действующих «противоположен», с учётом инверсий) получает желаемое мнение за счёт добавочных истинных `opp`/`same` в ветвях вне опоры; бот `degree` — за счёт дистракторов, задевающих сущности вывода.
- **Семейные боты:** `parity`, `degree`, `endpoint` (если обе сущности вывода — листья, отвечает по чётности).
- **Модель:** «Одна сторона: ВОЛ, ДЕК · Другая сторона: ЗУМ, ПАЙ».

### 5.2 `orderNum` / `orderTime` — «Сравнение чисел» / «Порядок во времени»

- **Мир:** позиции 1…n (ранг; больше/позже = выше).
- **Посылки:** `gt(a,b)` — «A больше, чем B» или, для того же ребра, «B меньше, чем A» (время: «позже/раньше»); `between(m; a,b)` — неупорядоченное «По величине M — между A и B» / «M произошло между A и B» (две модели: A<M<B или B<M<A); только для времени: `succ(a,b)` «A произошло сразу после B» (L ≥ 5), `gap(a,b,k)` «Между A и B произошло ровно k событий» (L ≥ 8); `extreme(a)` «A — самый большой» / «A произошло первым» (L ≥ 8, редко).
- **Вопросы:** `gt`/`lt` (любая формулировка), `between` (L ≥ 6); формат `choice` «Кто третий по величине?» (L ≥ 3, до 20% заданий, варианты — все имена + «Нельзя определить»).
- **Решатель:** перестановки с отсечением (n ≤ 8); для `supportDomain: 'restricted'` — ранги только среди сущностей подмножества, кроме `succ/gap/extreme` (с ними — инъекция в полный набор позиций).
- **Приманки:** `reversal` — обратное к необходимому отношению; `possible` — неопределённое, но верное в предпочтительной модели (сущности расставлены в порядке первого упоминания, свободные места заполняются «по ходу чтения»); `nearMiss` — для `between`: неверная середина; `surface` — пара встречалась в одной `between`-посылке, а спрашивается `gt`.
- **Контроль подсказок:** как в прототипе — добавлять истинные сравнения, задевающие сущности вывода, пока бот `netScore` не даст желаемое мнение; затем проверить ответ, σ и нелокальность.
- **Семейные боты:** `netScore` («счёт побед»), `degree`, `subject` (кто чаще стоит подлежащим).
- **Модель:** «ДЕК < ВОЛ < ЗУМ < ПАЙ» (время: «ДЕК → ВОЛ → ЗУМ → ПАЙ, от раннего к позднему»).

### 5.3 `syllogism` — «Силлогизмы» (замена «Каньона» и «Фредо»)

- **Семантика:** классическая силлогистика, все названные категории непусты (экзистенциальный импорт), как сейчас. Явно написать это в уроке.
- **Посылки:** `all`, `no`, `some`, `some_not` (текущие русские формы годятся). Инверсия — **на каждую посылку отдельно** с вероятностью `negationRate` (сейчас один флаг на всё задание, что само по себе подсказка).
- **Вопросы:** любая упорядоченная пара терминов × 4 квантора, кроме прямо сформулированных (учитывая симметрию `no` и `some`).
- **Классификация:** `entailed` — `entails(P, q)`; `contradicted` — `entails(P, ¬q)`; иначе `undetermined`. Решатель — перенос `sylIsConsistent`/`sylEntails`; оракул в тестах — перебор областей диаграммы Венна для ≤ 4 терминов.
- **Стратификация (ключевое):** ячейки = ответ (3) × квантор вывода (4) × согласован ли вывод с «атмосферой» посылок (2) × является ли субъект вывода субъектом какой-либо посылки (2). Планировщик выбирает ячейку равномерно среди достижимых; счётчики ведутся по семейству. Это убивает приор «Все → неверно» (сейчас 74–80%).
- **Конструкция:** ядро-цепочка длины σ по таблице `SYL_TRUE_CONCLUSIONS` (для `entailed` выводит q, для `contradicted` — ¬q, для `undetermined` — содержит одно недопустимое звено), дистракторы привязаны к терминам ядра, их кванторы подбираются под нужную «атмосферу». Проверить: совместность, класс, точное σ («нет более короткого доказательства» — общим поиском опоры, а не путями).
- **Генератор «Фредо» удалить**, выбор генератора из настроек убрать (ключ `SYL_SYLLOGISM_GENERATOR` игнорировать). Классические двухпосылочные силлогизмы = уровень 1–2 нового генератора.
- **Семейные боты:** `atmosphere` (Woodworth–Sells), `quantifierPrior`, `matching` (квантор вывода совпадает с квантором посылки, имеющей общий термин → «следует»), `conversion` (незаконное обращение «все A — B» ⇒ «все B — A», «некоторые A не B» ⇒ «некоторые B не A», затем решатель), `figural` (порядок терминов).
- **Разбор:** опора + для `undetermined` контрпример из «объектов-свидетелей»: по свидетелю на каждый термин, каждую `some`/`some_not` и на ¬q; принадлежности — замыкание вверх по включениям, вне — по непересечениям; модель проверяется прямой подстановкой, при неудаче показывается только опора. Текст: «Возможен мир: объект 1 — ВОЛ и ДЕК, не ЗУМ; объект 2 — ДЕК и ЗУМ».

### 5.4 `linear` — «Линейный порядок»

- **Мир:** позиции 1…n слева направо (с точки зрения наблюдателя).
- **Посылки:** `left` «A стоит левее, чем B»; `immLeft` «A стоит сразу слева от B»; `adj` «A и B стоят рядом»; `notAdj` «A и B стоят не рядом» (L ≥ 4); `between` «Из A, B и C посередине стоит B» (не обязательно вплотную); `dist` «A и B разделяют ровно k человек» (L ≥ 5); `steps` «A стоит на k позиций левее, чем B»; `end`/`notEnd` «A стоит с краю / не с краю» (L ≥ 6); `pos` «A стоит k-м слева» (только L ≤ 9, редко).
- **Вопросы:** те же виды, кроме `pos`; формат `choice` «Кто стоит k-м слева?».
- **Исправление утечки:** инструкция «Участники: …» перечисляет имена **в алфавитном порядке** с пометкой «(порядок в списке — алфавитный)». Поле `question.rule` с порядком больше не заполнять.
- **Приманки:** `reversal` (сторона), `nearMiss` (k ± 1 в `steps`/`dist`), `possible`, `surface`.
- **Семейные боты:** `instructionOrder` (читает порядок из инструкции — обязан быть на уровне случайности), `relationTypePrior`, `stepMagnitude` (k вывода против максимального k в посылках), `degree`.
- **Модель:** «[ДЕК] [ВОЛ] [ЗУМ] [ПАЙ]» слева направо.

### 5.5 `circular` — «Круговой порядок»

- **Мир:** n мест за круглым столом, все сидят лицом к центру. Договорённость в тексте инструкции: «„Слева от A“ — с точки зрения A, сидящего лицом к центру». Технически: места пронумерованы по часовой стрелке (вид сверху), сосед слева = следующее место по часовой.
- **Посылки:** `immLeft`/`immRight`; `adj`, `notAdj`; `opposite` «A сидит напротив B» (n чётное); `gap` «Между A и B по короткой дуге ровно k человек»; `between` «B сидит между A и C» (= A и C — оба соседа B).
- **Решатель:** e0 фиксирован на месте 0, перебор остальных ((n−1)! ≤ 5040).
- **Утечка инструкции** — исправить так же, как в 5.4 (алфавит).
- **Семейные боты:** `instructionOrder` (циклический), `relationTypePrior`, `degree`.
- **Модель:** «По часовой: ДЕК → ВОЛ → ЗУМ → ПАЙ → (ДЕК)».

### 5.6 `dir2d` — «Направления 2D»

- **Мир:** целые координаты (x — восток, y — север); совпадение клеток не запрещено, если не сказано.
- **Посылки:** точные — «A на 2 шага севернее и на 1 шаг восточнее, чем B», «A в соседней клетке к северо-востоку от B» (|dx|, |dy| ≤ 1); качественные — «A севернее, чем B» (yA > yB, x любой), «A северо-восточнее, чем B» (обе оси), «A строго севернее, чем B» (yA > yB, xA = xB), «A и B на одной вертикали / горизонтали».
- **Примечание в задании** (вместо нынешнего «Направления точные…»): «„Строго севернее“ — на той же вертикали. „Севернее“ — выше по карте, по горизонтали где угодно».
- **Решатель:** по осям — система разностных ограничений (`dcs.ts`): переменные — координаты, ограничения `x_a − x_b ≤ c` (равенства — двумя неравенствами, строгие — через ±1), Флойд–Уоршелл даёт для каждой пары диапазон `[lo, hi]` (возможны ±∞). Вопрос по оси — допустимое множество разностей: следует, если `[lo, hi] ⊆ allowed`; противоречит, если пересечение пусто; иначе неизвестно. Вопрос по двум осям — конъюнкция: следует, если обе следуют; противоречит, если хоть одна противоречит; иначе неизвестно (оси независимы).
- **Исправления:** (1) фраза «в соседней клетке» и величины шагов распределены одинаково во всех классах ответа (стратификация по типу фразы и корзине величины шага); (2) ложные и неопределённые выводы берут величины шагов из того же распределения, что истинные; (3) рендер диагонали при частичной инверсии — см. 4.7.
- **Семейные боты:** `adjacencyPhrase` («соседняя клетка» → следует), `stepMagnitude` (шаг вывода больше максимального в посылках → противоречит), `axisCount`.
- **Модель:** мини-карта (CSS-сетка в разборе), для «неизвестно» — две карты.

### 5.7 `dir3dSpace` / `dir3dTime` — «Направления 3D» / «Пространство и время»

То же, что 5.6, плюс третья ось: пространство — «выше/ниже на k уровней», «на одном уровне»; время — «позже/раньше на k часов», «одновременно». Тот же решатель на трёх осях. Исправить подсказки: ложность больше не возникает из выхода за сетку, «та же точка» не означает автоматически «верно».

### 5.8 `graph` — «Сравнение графов» (v2)

Два подвида, чередуются:
- **`iso` (бинарный):** «Проверь, одинаково ли устроены две сети». Положительные — переименование + перестановка + обратные формулировки во второй сети («B получает от A» = A → B). **Отрицательные — перестройка с сохранением степеней:** выбрать два ребра одного типа `u1→v1`, `u2→v2` с четырьмя разными концами, заменить на `u1→v2`, `u2→v1` без дублей; 1–3 раза; требовать неизоморфность (точная проверка) при совпадении мультимножества сигнатур (вход, выход, взаимные) и числа рёбер каждого типа.
- **`map` (выбор):** «Найди во второй сети участника с той же ролью, что X в первой». Образ X единственный при всех изоморфизмах (перечислить изоморфизмы перебором с отсечением по сигнатурам). С L ≥ 6 цель «косвенная»: её сигнатура степеней есть ещё хотя бы у одной вершины.
- **Мир:** ориентированный граф, n = 4…8, рёбер n−1…⌊1.8n⌋; с L ≥ 6 добавляется тип «↔».
- **Метаотношения в графах убрать.**
- **Семейные боты и пороги:** `iso`: `degreeSequence`, `edgeTypeCount` ≤ 55%; `map`: `signature` (случайная вершина с той же сигнатурой) ≤ 1/(средний размер класса) + 5 п.п., на L ≥ 6 средний размер класса ≥ 2; `firstMention` (вершина с тем же номером первого упоминания) ≤ 1/n + 5 п.п.
- **Модель:** таблица соответствия «A ↔ K, B ↔ M, …».

### 5.9 `analogy` — «Аналогии»

- **Базовый мир** — одно из включённых: `groups`, `orderNum`, `orderTime`, `linear`, `circular`, `dir2d`.
- **Вопрос:** «Отношение A к B такое же, как отношение C к D?» с явной расшифровкой «такого же» для базы: группы — совпадение/несовпадение стороны; порядок — знак; ряд — сторона **и** расстояние; круг — расстояние по часовой; карта — вектор смещения.
- **Обе пары не названы прямо**; с L ≥ 4 каждая требует σ ≥ 2. Если хотя бы одна пара не определена так, чтобы сравнение было неопределённым, — ответ «неизвестно».
- **Формулировка** («такое же» / «отличается») выбирается независимо от ответа; стратификация по (база × формулировка × ответ).
- **Семейные боты:** `wordingPrior` (по базе и формулировке), `cooccurrence`.
- **Модель:** модель базового мира с выделенными парами.

### 5.10 `binary` — «Логические связки»

- Две подзадачи из движка (по возможности разных семейств), каждая с определённым ответом, на уровне `max(1, L − 3)`; имена не пересекаются; посылки перемешаны вместе; инструкции объединены.
- Связка — из включённых; итог по таблице истинности. Стратификация по (связка × итог × комбинация подответов TT/TF/FT/FF) — равномерно по достижимым. Это убирает перекос XOR/XNOR (59–60% сейчас).
- Формат — **только бинарный** («Верно/Неверно»).
- **Семейные боты:** `operatorPrior`, `firstOnly` (оценивает только первое утверждение).

**Приёмка фазы 1 (каждой подфазы):** тесты корректности 4.11 зелёные для перенесённых семейств; `npm run audit` проходит все гейты 4.10; в `docs/V5_NOTES.md` — таблица «до/после» по каждому перенесённому семейству (до — из `reports/legacy-v4.1-audit.txt`).

## 7. Фаза 3 — новый режим «Конструктор»

**Зачем.** Ответ — не кнопка, а построенная модель: угадать нельзя, обойти интеграцию нельзя. Сложность задаётся тем, сколько подсказок приходится держать одновременно, чтобы сделать очередной вывод (теория реляционной сложности), и тем, нужны ли гипотезы с откатом. Формат близок к логическим играм LSAT (группировка и упорядочивание по сложным правилам) — интенсивный курс на таких задачах сопровождался ростом визуопространственного рассуждения и укреплением лобно-теменных связей (квазиэксперимент, без рандомизации).

### 7.1 Миры

| Тип | Размер | Число миров (для перебора) |
| --- | --- | --- |
| `line` — ряд | n = 4…7 | до 5 040 |
| `circle` — круглый стол | n = 5…7 | до 720 |
| `groups` — 2–3 названные группы с объявленными размерами | n = 5…8 | сотни |
| `lineAttr` — ряд + цвет (2–3 цвета, каждый используется) | n = 4…5 | до ≈ 18 000 |
| `grid` — сетка 3×3, 5 участников, пустые клетки | n = 5 | 15 120 |

### 7.2 Подсказки

- Бинарные: левее, сразу слева, рядом, не рядом, с краю, не с краю, k-й слева (только низкие уровни), в одной группе, в разных группах, цвет, не этот цвет, в одной строке/столбце, выше, левее в строке.
- Тернарные: «Из A, B и C посередине — B»; «A ближе к B, чем к C»; «A и B по разные стороны от C»; «Рядом с A сидит ровно один из B и C».
- Условные: «Если A в группе Альфа, то B — в группе Бета»; «Если A стоит с краю, то B стоит рядом с C».
- Количественные: «Между A и B ровно k человек»; «В группе Альфа ровно двое из A, B, C»; «Синих ровно двое».

### 7.3 Генерация

1. Перечислить все миры выбранного типа один раз (кэш) и случайно выбрать истинный мир W.
2. Построить пул истинных в W подсказок (все шаблоны на кортежах сущностей; условные — выборка).
3. **Битсеты:** для каждой подсказки — битсет миров, где она истинна (`Uint32Array`). Пересечение — побитовое И, это делает дальнейший поиск дешёвым.
4. Жадно добавлять подсказку с максимальным `log2(|M| / |M ∧ c|) × вес_типа(c, L)` (случайный выбор среди трёх лучших), пока не останется один мир.
5. Минимизировать: удалить любую подсказку, без которой решение остаётся единственным.
6. Добавить избыточные истинные подсказки-дистракторы по уровню.
7. **След дедукции:** факты — «сущность → позиция / группа / цвет». Пока не все факты известны: найти наименьшее k и подмножество из k подсказок, которое вместе с уже известными фактами фиксирует новый факт; записать шаг. Если до `kMax` такого нет — шаг-гипотеза (нужен перебор), `caseSplit = true`. Метрики: `entryK` (k первого шага), `maxK`, число шагов, `caseSplit`, доли тернарных и условных подсказок.
8. Принять, если метрики в цели уровня, иначе новая попытка (≤ 30), затем ослабление с записью.

| Уровень | Мир | Подсказки | Цель метрик |
| --- | --- | --- | --- |
| 1–3 | line 4–5 | только бинарные | maxK ≤ 2, без гипотез |
| 4–6 | line 5–6 | ≥ 1 тернарная | maxK 2–3, с L5 entryK ≥ 2 |
| 7–10 | line 6–7, circle, groups | + условные, 1 дистрактор | maxK 3 |
| 11–14 | lineAttr, grid | 1–2 дистрактора | maxK 3–4, entryK ≥ 2 |
| 15–20 | любые | все типы | одна гипотеза допустима, maxK 4 |

### 7.4 Варианты задания

- `build` (70%) — расставить всех.
- `mustBe` (15%) — какое из 4 утверждений обязано быть верным (ровно одно).
- `count` (15%) — сколько расстановок удовлетворяет подсказкам: 1 / 2 / 3 / 4+ (набор подсказок специально оставляет нужное число).

### 7.5 Интерфейс

Поле под тип мира (клетки ряда, места за столом, колонки групп, сетка), чипы участников, «нажми чип → нажми клетку» (удобно на телефоне), «Отменить», «Сбросить», «Проверить». Первая проверка сообщает только **сколько** стоят верно; вторая — полный разбор: неверные размещения, нарушенные подсказки, пошаговый след дедукции («Шаг 1. Подсказки 2 и 5: ВОЛ может стоять только третьим»).

### 7.6 Лестница и производительность

Решено с первой проверки — успех; со второй — уровень не меняется; не решено — ошибка. Отдельная лестница на режим, цель 70%. Генерировать следующую задачу во время разбора; если в браузере p95 > 300 мс — перенести генерацию в Web Worker (`ng generate web-worker`), иначе оставить в основном потоке.

**Приёмка фазы 3:** тесты — единственность решения, минимальность (каждая подсказка нужна, кроме объявленных дистракторов), согласованность следа дедукции, метрики в целях уровня; бот «подсказки по одной» (фильтрует домены каждой подсказкой отдельно, затем угадывает) на уровнях ≥ 5 не решает больше 10% задач; p95 генерации ≤ 400 мс (Node).

## 8. Фаза 4 — новый режим «Отображение структур»

**Зачем.** Это уровень «отношения между сетями отношений» (MDML, уровень 5), которого в v4.1 нет совсем. Задача на поиск соответствия ролей в двух графах — один из самых сильных простых индикаторов Gf (нагрузка .75 на Gf, почти как у самих тестов рассуждения; r ≈ .61 с Равеном), а сравнение структур с разным «покрытием» даёт абстракцию схемы.

### 8.1 Виды заданий

- `map` (60%): две системы с разным словарём и именами; «Кто во второй системе играет роль X?» — выбор из всех участников второй системы.
- `iso3` (20%): три системы; «Какая из систем 2 и 3 устроена так же, как система 1?» — ровно одна изоморфна, вторая — приманка с тем же набором степеней (перестройка из 5.8).
- `anchor` (20%): граф с нетривиальной симметрией; дано одно соответствие («X соответствует K»), оно снимает симметрию; «Кому соответствует Y?».

### 8.2 Системы и словарь

Ориентированные графы, n = 4…8, рёбер n−1…⌊1.8n⌋; с L ≥ 8 — два типа отношений. Словарь (пары с обратными формулировками): «пишет письма» / «получает письма от»; «обучает» / «учится у»; «охотится на» / «служит добычей для»; «передаёт сигнал» / «получает сигнал от»; «руководит» / «подчиняется»; симметричные — «дружит с», «соседствует с», «работает вместе с». Вторая система — другой словарь (с L ≥ 4 — часто обратная формулировка), другие имена, свой случайный порядок утверждений. С L ≥ 12 соответствие типов отношений переставлено (первое отношение второй системы соответствует второму первой) — его надо вывести из структуры.

### 8.3 Корректность и сложность

- Образ цели единственный при всех изоморфизмах (включая биекции типов отношений); для `anchor` — единственный с учётом опорного соответствия.
- Лестница: n, рёбра, доля «косвенных» целей (сигнатура степеней не уникальна), обратные формулировки, два типа, перестановка типов, похожие имена. Цель 70%.
- Боты на уровне случайности: `signature`, `firstMention`, `wordPosition`, `degreeSequence` (для `iso3`).

### 8.4 Разбор и интерфейс

Таблица соответствий + подсветка тех связей, которые отличают цель от её «двойника». Системы — карточки рядом (на телефоне — друг под другом). Только текст: визуальная версия с рисованными графами — это проба переноса в фазе 7, её нельзя тренировать.

**Приёмка фазы 4:** тесты единственности и корректности соответствий (оракул — перебор перестановок), гейты ботов, отдельная лестница режима.

## 9. Фаза 5 — новые фреймы

RFT выделяет семейства отношений, которых в v4.1 нет: иерархия, условие/причина, дейктические («я–ты», «здесь–там»). Каждое — новое семейство в движке по контракту 4.2, с тестами 4.11, гейтами 4.10, уроком и новым значением в `EnumQuestionType`. Открываются на tier 6–7.

### 9.1 `conditional` — «Условия»

- **Мир:** булевы значения n = 3…7 «ламп»: «Лампа ВОЛ горит / не горит».
- **Посылки:** «Если горит A, то горит B» (и варианты с «не горит» в любой части); «A горит, только если горит B» (≡ если A, то B); «Горит A или B (возможно, обе)»; «Горит ровно одна из A и B»; «A и B не горят одновременно»; «A горит тогда и только тогда, когда горит B» (L ≥ 6); факты «A горит» / «A не горит».
- **Вопросы:** литерал («C горит») и условное утверждение («Если B горит, то D не горит»).
- **Решатель:** перебор 2ⁿ.
- **Приманки:** утверждение следствия (из «если A, то B» и «B» — «A»), отрицание основания, перевёрнутое «только если», `possible`.
- **Семейные боты:** `matching` (литерал стоит следствием правила с истинным фактом-основанием → «следует»), `polarity` (по числу «не»).
- **Модель:** «Горят: A, C · Не горят: B, D».

### 9.2 `hierarchy` — «Иерархия»

- **Мир:** лес «часть → непосредственное целое» на n ≤ 6 сущностях, у каждой части не больше одного непосредственного целого.
- **Посылки:** «A — часть B» (на любой глубине); «A непосредственно входит в B» (L ≥ 4); «A — не часть B»; «A и B непосредственно входят в одно и то же целое»; «A ни во что не входит».
- **Ключевой нелокальный вывод:** если A — часть B и A — часть C, то B — часть C или C — часть B. Генератор должен регулярно требовать именно такие выводы.
- **Вопросы:** «A — часть B» / «A — не часть B».
- **Решатель:** перебор массивов родителей с отбрасыванием циклов; `supportDomain: 'full'`.
- **Модель:** дерево отступами.

### 9.3 `perspective` — «Точка зрения»

- **Мир:** n = 3…6 человек в ряд (позиции слева направо для тебя), каждый стоит лицом к тебе или спиной.
- **Посылки:** «Для A справа стоит B» (если A спиной к тебе — это твоё «справа», если лицом — твоё «слева»); «A и B смотрят в одну сторону / в разные стороны»; «A стоит лицом к тебе»; «Для тебя A левее, чем B». Без местоимений, чтобы не зависеть от рода имён.
- **Вопросы:** отношение с точки зрения любого участника или твоей, направление взгляда.
- **Решатель:** n! · 2ⁿ.
- **Семейные боты:** `egocentric` (читает все «для X» как «для тебя») — обязан быть на уровне случайности; `word`.
- **Модель:** «[ВОЛ ↑] [ДЕК ↓] [ЗУМ ↑]» (↑ — спиной к тебе, ↓ — лицом к тебе).

### 9.4 `groups3` — «Три группы»

Как `groups`, но групп три: «A и B в одной группе» / «A и B в разных группах». «В разных группах» не транзитивно, поэтому «неизвестно» возникает в связном графе естественно (A≠B, B≠C ⇒ про A и C неизвестно). Решатель — 3ⁿ с симметрией.

## 10. Фаза 6 — режим «Беглость»

**Зачем.** Автоматизировать базовые выводы (взаимное и комбинаторное выведение) и гибкость контекстного управления, чтобы освободить ресурс для глубокой интеграции. Честно: скорость таких выводов тренируется, перенос на Gf не доказан. Доля в тренировке — 10–15%.

- Блоки по 30 заданий, только бинарный ответ, σ = 2, 2–3 посылки, определённые ответы; семейства чередуются в каждом задании.
- Дедлайн на семейство D, старт 7 с, границы 1.5–15 с: верно в срок → `D ×= 0.97`; ошибка или тайм-аут → `D ×= 1.19` (равновесие ≈ 85% верных).
- Счёт — правило «знаковой остаточной скорости»: за задание `S = (2x − 1)·(D − t)/D` (x = 1 при верном ответе, t — время). Быстрые ошибки наказываются, угадывание невыгодно.
- **Блоки контекстного контроля** (каждый третий): слова отношений заменены произвольными псевдословами (например, «ВУЛ» = больше, «ТЭК» = меньше; свои пары на каждый блок), легенда 10 с перед блоком и по удержанию `L`. Цвет рамки — контекст: синий — обычное значение, оранжевый — значения поменялись местами; цвет меняется в каждом задании с вероятностью 0.3.
- Обратная связь — только короткая вспышка цвета; сводка в конце блока; своя статистика (дедлайн по семействам, точность, очки).

## 11. Фаза 7 — «Контроль переноса» и аналитика

**Зачем.** Дальний перенос, если он есть, идёт через ближний. Нужны форматы, которые **никогда не тренируются**, чтобы видеть реальный перенос, а не рост навыка в тренажёре.

- Раздел «Контроль переноса», напоминание раз в 14 дней. Сессия около 15 минут, **без обратной связи**, отдельное хранилище `SYL_V5_PROBES`, на уровни не влияет.
- Пробы (альтернативные формы по seed `probe:<дата>`, сложность сбалансирована между сессиями):
  1. **Латинский квадрат 4×4**, 10 заданий: выбрать фигуру для клетки «?» из 4. Реляционная сложность задания = сколько строк и столбцов с видимыми клетками надо рассмотреть совместно, чтобы определить клетку (1 / 2 / 3) — считать перебором по подмножествам линий.
  2. **Числовые ряды**, 8 заданий: арифметическая и геометрическая прогрессии, две чередующиеся прогрессии, вторые разности, «фибоначчиподобные»; ответ — число.
  3. **Визуальное отображение графов**, 8 заданий: два нарисованных (SVG) графа со случайной раскладкой, одно- и двунаправленные стрелки; кликнуть вершину второго графа, соответствующую выделенной в первом. Сложность: 3–6 рёбер, пересечения, косвенные цели.

- Текст пояснения: «Рост здесь — ближний перенос. Если его нет 4–6 недель, роста Gf ждать не стоит — меняй смесь режимов».

## Приложение A. Карточки стратегий и подсказки

1. **Одна модель.** Собери все посылки в одну картину (ряд, карту, группы), а не держи их отдельными фактами.
2. **Начни с самой связывающей посылки** — той, что касается большего числа участников или трёх сразу.
3. **Ищи контрпример.** Перед «Следует» попробуй построить мир, где вывод ложен.
4. **«Неизвестно» — полноценный ответ:** если нашлись два мира с разными ответами.
5. **Отдели нужное:** найди посылки, которые связывают слова из вывода через другие слова, остальное отложи.
6. **Отпусти прошлое задание:** имена повторяются в новых ролях.
7. **Красное слово — сразу перекодируй** в противоположное, прежде чем строить модель.

Подсказки в разборе по типу ловушки: `possible` → карточка 3–4; `reversal` → «Проговори направление: кто левее, кто больше»; `nearMiss` → «Отношение верное, проверь величину»; `surface` → карточка 5; ошибка в задании с `carryOver` → карточка 6; ошибка при инверсиях → карточка 7.

## Приложение B. Чего не делать

- Не вводить очки или серии за скорость в глубоких режимах (подталкивают к эвристикам; скорость — только в «Беглости»).
- Не группировать задания одного типа в серии.
- Не делать число посылок единственным рычагом сложности.
- Не показывать в инструкциях и списках ничего, что коррелирует с ответом (порядок, длину, «особые» слова).
- Не поднимать порог гейта, чтобы аудит прошёл: чинить генератор.
- Не обещать в интерфейсе рост интеллекта и не показывать «IQ».

## Приложение C. Глоссарий метрик

| Метрика | Смысл |
| --- | --- |
| σ (опора) | Минимальное число посылок, из которых следует ответ (глубина вывода) |
| Ширина | Число сущностей в опоре и выводе (нагрузка на связывание) |
| Арность | 2 — бинарное отношение, 3 — «между», 4 — метаотношение |
| Сходимость | Опора не простая цепь: ветви сходятся, есть тернарные посылки |
| Нелокальность | Ответ не выводится из посылок, касающихся слов вывода |
| log2 моделей | Насколько посылки оставляют мир неопределённым |
| Дистракторы | Лишние посылки; «привязанные» — с общими словами с опорой |
| Разрывность | Доля соседних посылок без общих слов |
